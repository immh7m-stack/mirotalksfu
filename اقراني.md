# نظرة عامة وتشغيل MiroTalk SFU على سيرفر مستقل

هذا المستند يشرح المشروع باختصار ويعطي خطوات مفصّلة لتشغيله على سيرفر مستقل (public server / VPS) — ليس localhost.

---

## 1) ما هو هذا المشروع

MiroTalk SFU منصة مؤتمرات فيديو مبنية على معماريّة SFU (mediasoup). تشمل واجهة ويب، REST API، دعم RTMP وخيارات تسجيل واجتماعات متعددة.

## 2) المتطلبات الأساسية للسيرفر (Ubuntu مثال)

- نظام تشغيل: Ubuntu 20.04/22.04/24.04 أو توزيعة Linux حديثة
- Node.js (موصى به v22.x)
- npm
- build-essential, python3, pkg-config, ffmpeg
- nginx (لـ reverse proxy & SSL)
- certbot (Let's Encrypt) أو شهادات SSL صالحة
- (اختياري لكن موصى) coturn كخادم TURN

أوامر تثبيت أساسية (Ubuntu):

```bash
sudo apt update
sudo apt install -y build-essential python3 python3-pip ffmpeg nginx certbot \
  certbot-nginx curl git
# تثبيت Node 22 (مثال باستخدام NodeSource)
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
```

لـ coturn:

```bash
sudo apt install -y coturn
```

## 3) نسخ المشروع وإعداد المتغيرات

على السيرفر، انسخ المشروع:

```bash
git clone https://github.com/immh7m-stack/mirotalksfu.git
cd mirotalksfu
```

انسخ الملفات الإرشادية إلى ملفات الإعداد الفعلية:

```bash
cp app/src/config.template.js app/src/config.js
cp .env.template .env
cp docker-compose.template.yml docker-compose.yml
```

عدّل `env` و `app/src/config.js` بما يناسب نطاقك (domain) وعناوين الشبكة. أهم متغيّرات يجب تعديلها:

- `SERVER_HOST_URL` أو `SERVER_LISTEN_IP`/`SERVER_LISTEN_PORT`
- إعدادات `mediasoup` (announcedIP في حال استخدام NAT)
- إعدادات `TURN` (coturn) إن وُجدت

مثال: ضع في `.env`:

```text
SERVER_LISTEN_IP=0.0.0.0
SERVER_LISTEN_PORT=3010
SERVER_HOST_URL=https://meet.example.com
```

وعدّل في `app/src/config.js` حقول `sfu.announcedIP` إلى عنوان الـWAN (أو اسم الشبكة الافتراضية) إن كنت خلف NAT.

## 4) فتح البورتات المطلوبة في الجدار الناري

افتح البورتات التالية (ufw مثال):

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 3010/tcp
# نطاق بورتات RTP لوسائط mediasoup
sudo ufw allow 40000:40100/udp
sudo ufw allow 40000:40100/tcp
```

إذا ستستخدم RTMP (اختياري): `sudo ufw allow 1935/tcp`.

## 5) إعداد nginx كـ reverse-proxy مع WebSocket و SSL (Let's Encrypt)

ملف مثال للموقع `/etc/nginx/sites-available/mirotalk`:

```nginx
server {
    listen 80;
    server_name meet.example.com;
    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl http2;
    server_name meet.example.com;

    ssl_certificate /etc/letsencrypt/live/meet.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/meet.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3010;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

بعد إنشاء الملف شَغّل:

```bash
sudo ln -s /etc/nginx/sites-available/mirotalk /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
# احصل على شهادة TLS
sudo certbot --nginx -d meet.example.com
```

ملاحظة: تأكد أن `SERVER_HOST_URL` في `config.js` يستخدم `https://meet.example.com`.

## 6) تشغيل التطبيق (systemd) — موصى

إنشاء ملف systemd `/etc/systemd/system/mirotalk.service` مثال:

```ini
[Unit]
Description=MiroTalk SFU
After=network.target

[Service]
Type=simple
WorkingDirectory=/home/ubuntu/mirotalksfu
Environment=NODE_ENV=production
ExecStart=/usr/bin/node app/src/Server.js
Restart=always
User=ubuntu
RestartSec=5

[Install]
WantedBy=multi-user.target
```

ثم:

```bash
sudo systemctl daemon-reload
sudo systemctl enable mirotalk.service
sudo systemctl start mirotalk.service
sudo journalctl -u mirotalk.service -f
```

بديل: يمكنك استخدام `pm2` لتشغيل وإدارة العملية.

## 7) بديل Docker (Docker Compose)

إذا تفضّل استخدام Docker:

```bash
# تأكد من تعديل docker-compose.yml إذا لزم
docker-compose pull
docker-compose up -d
```

في حالة Docker تأكد من تمرير نطاق بورتات RTP وتهيئة الشبكة الصحيحة وannounced IP.

## 8) إعداد TURN (coturn)

لتسهيل عمل WebRTC خلف NAT أو عبر شبكات صارمة، قم بتثبيت وإعداد `coturn`. عيّن بيانات `TURN` في `app/src/config.js` أو `.env`، ثم أعد تشغيل الخدمة.

## 9) فحوصات واستكشاف أخطاء شائعة

- تأكد أن الخدمة تعمل: `sudo systemctl status mirotalk.service` أو `ps aux | grep node`
- راجع اللوجات: `sudo journalctl -u mirotalk.service -n 200 --no-pager`
- تحقق من استماع على البورت 3010: `ss -tulpn | grep 3010` أو `netstat -anp | grep 3010`
- تحقق من فتح نطاقات RTP (40000-40100)
- إذا المتصفح يرفض الاتصال: افحص nginx (وجود شهادة)، وتحقق من أن `proxy_pass` يشير للمنفذ الصحيح، وتحقق من أن Node يعمل.

## 10) خطوات سريعة للنشر (ملخّص)

1. جهز السيرفر (Node, build tools, ffmpeg, coturn)
2. انسخ المشروع وعدّل `.env` و `app/src/config.js` لوضع النطاق وannouncedIP
3. افتح الجدار الناري للبورتات المطلوبة
4. جهّز nginx وشهادة TLS
5. شغّل باستخدام `systemd` أو `pm2` أو `docker-compose`
6. راجع اللوجات واختبر عبر `https://meet.example.com`

---

إذا تريد، أقدر أعمل لك ملف `systemd` مخصص يملأ المسارات باسم المستخدم لديك، أو أجهز ملف `docker-compose.override.yml` بمثال مع `TURN` وبيانات النطاق.
